# 三分钟项目介绍与演示视频脚本

适用版本：P9 FPGA / 板端3.13.0-p9 / Qt ui40-p9，含最新文字调整。
总时长180秒。题目建议：**基于FPGA与NPU协同的PCB视觉检测系统**。

赛题依据：《安路赛题解读.pdf》PDF第19、22、25、26页。以采集、FPGA硬件预处理与压缩、PCIe互通、NPU检测、量化数据为主线，串联本项目现有功能，不宣称全部高级指标已经达标。

## 压缩段如何拍出证据

1. 固定摄像头和PCB位置，在同一分辨率下演示无损与RAW6有损切换。
2. 无损段讲“完整保留源数据”，不把界面中的0%当作真实无损压缩率；该值是当前Qt展示约定，真实字节和节省率仍可在悬浮提示中查看。
3. RAW6段拍到实际收到的原始源字节与PCIe包字节，再用实际计数写字幕。P9完整帧RTL验证的参考值如下，不等于本轮新增的板卡现场测量：

| 彩色模式 | 原始源字节 | 含封装PCIe字节 | 完整帧RTL验证节省率 |
| --- | ---: | ---: | ---: |
| 1080P | 2,667,904 | 1,667,536 | 37.4964% |
| 单路4K | 10,591,744 | 6,619,936 | 37.4991% |

如果拍摄时真实状态确实显示上述数量，可以加字幕“FPGA有损传输数据量减少约37.5%（含封装）”。没有拍到有效实际计数时，字幕注明“完整帧RTL验证”，不要标作现场实测。
4. RAW6/灰度5位属于有损位打包，不称为“LZ77有损”或“FPGA JPEG”。RK硬件JPEG是独立的后端预览链路。
5. 拍硬件JPEG段之前，核对运行状态中的 `channels.A/B.transport.encoder` 是 `RK MPP JPEG`。项目保留OpenCV CPU回退；若实际回退，不用硬件JPEG旁白，改成“后端通过JPEG完成网络预览”。

## 拍摄前准备

- 启动当前 `pc_qt_p9/start_dual_station.bat`，不要打开原 `pc_qt` 或已放弃的集中布局试用版。
- 提前准备三类缺陷样板、均匀照明与清楚焦点；所有框和告警来自当前真实样本。图像调节演示时关闭该路检测，恢复彩色后再开启检测。
- 提前接好HDMI、连接手机热点并取得无线IP。手机访问 `http://无线IP:8001/m`，对应路Wi-Fi推送开启；不要把同热点局域网访问称为4G云端推送。
- 先确认SD卡和本地目录均可写。截图文件里的数量取实际检测结果，目录与文件都拍本次真正保存的内容，不只展示预先摆好的空文件夹。
- 测量段先完成当前相机、焦距和PCB高度对应的有效标定，只说“板框尺寸初测”，不宣称误差小于0.1mm。
- 先分段录屏，再按本表剪为180秒。模式切换等待可剪开；用于展示响应、帧率和运动的片段保持原速，不通过加速、插帧或改数值表现性能。

## 指标字幕的口径

- 采集fps、Qt预览fps、推理耗时分开，视频帧率不等于推理频率。
- “传输确认延迟”包含读取、解码和ACK回程，不写成完整端到端延迟。
- FPGA资源卡来自P9最终布线报告，是静态占用，不是实时负载。
- P9已由用户反馈正常出图；本脚本没有新增现场压缩/帧率/检测精度测量。拍摄字幕使用当时有效状态。
- 不预填未验证的同步误差、识别准确率、测量精度、长期无故障或4K无损30fps结论。
